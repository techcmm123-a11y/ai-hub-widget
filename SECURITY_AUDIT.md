# Аудит безопасности и приватности: AI Start 1.6

Дата: ноябрь 2026. Объект: исходный код, манифест, ресурсы, сборочный процесс и репозиторий проекта.

## Важная оговорка

Это самопроверка, выполненная ИИ-ассистентом по исходному коду: статический разбор и автоматические поиски по проекту.
Это **не независимый аудит**. Не проверялись: поведение на реальном устройстве, динамический анализ (перехват трафика,
отладчик), собранный APK, сторонние сканеры. Перед публичной раздачей приложения другим людям стоит проверить его
инструментами из раздела 7 и, при возможности, показать человеку с опытом в Android-безопасности.

## 1. Краткий итог

Риск для пользователя **низкий**. У приложения нет разрешений, нет сетевого кода, нет сторонних библиотек и SDK,
нет аналитики, нет входа в аккаунты и нет хранения паролей или токенов. Основные данные: список выбранных ИИ-сервисов,
подписи входов и ссылки. Они хранятся только в закрытом хранилище приложения.

Главные риски связаны не с кодом, а с тем, **как приложение раздаётся**: публичный отладочный ключ подписи и
отладочная сборка (раздел 5, пункты S9 и S10). Для личной установки это приемлемо, для раздачи другим нет.

В ходе аудита найдено и исправлено в версии 1.6: S1, S2, S3, S11 (см. таблицу).

## 2. Что проверено автоматически

| Проверка | Результат |
|---|---|
| Объявленные разрешения (`uses-permission`) | нет ни одного |
| Сетевой код (HTTP, сокеты, WebView, библиотеки) | отсутствует |
| Сторонние зависимости приложения | нет (только Android SDK) |
| Аналитика, рекламные и краш-SDK | нет |
| Логирование (`Log.*`, `println`, `printStackTrace`) | нет |
| `PendingIntent`: способ создания | везде `FLAG_IMMUTABLE`, явные компоненты |
| `FLAG_MUTABLE` | не используется |
| Экспортированные компоненты | `MainActivity` (запуск), три приёмника виджетов (требуется системой) |
| Неэкспортированные | `EntryActivity`, `LaunchActivity`, `ChooserActivity` |
| `allowBackup` | `false` |
| Секреты в репозитории (пароли, токены, ключи API, почта) | не найдено |
| Файлы ключей в репозитории | только публичный отладочный `app/debug.keystore` (пароль `android`) |

## 3. Приватность: какие данные и где

| Данные | Где хранятся | Передаются ли куда-то |
|---|---|---|
| Выбранные ИИ, порядок, формы значков, тема, язык | закрытое хранилище приложения (SharedPreferences) | нет |
| Подписи входов («Личный», «Работа»), ссылки, имена пакетов браузеров и приложений | там же | нет |
| Список установленных приложений | читается на лету, на диск не сохраняется (кроме выбранных пакетов) | нет |
| Резервная копия настроек | буфер обмена, по нажатию пользователя | только если пользователь сам её вставит куда-то |
| Пароли, токены, переписка, содержимое чатов | не обрабатываются и не хранятся | нет |

Что важно знать честно:

- **Список приложений.** Приложение объявляет запрос на просмотр приложений с значком запуска и использует его,
  чтобы найти ваши ИИ-приложения и предложить выбор. Это чувствительная возможность (по списку приложений можно
  многое понять о человеке). Здесь список не покидает телефон, а в разделе «О приложении» об этом сказано явно.
- **Подписи входов** могут содержать личное («Мама», «Клиент X»). Они лежат в хранилище приложения без шифрования
  (оно защищено системой, но читается при root-доступе и при отладке отладочной сборки).
- **Открытие сайтов и Google Play.** Когда вы нажимаете кнопку, приложение просит браузер или Play открыть страницу.
  Сетевой запрос делает браузер или Play, а не AI Start. Что они при этом собирают, определяют их политики.
- **Резервная копия** содержит подписи, ссылки и имена пакетов. Не публикуйте её в открытых местах
  (в том числе в Issues репозитория).

## 4. Модель угроз (кто и как может навредить)

| Угроза | Оценка |
|---|---|
| Вредоносное приложение на телефоне пытается управлять виджетом или кнопками | Низкая: команды виджета закрыты секретной меткой (S2), `PendingIntent` неизменяемые, чужое приложение не может запустить внутренние экраны |
| Вам прислали «резервную копию» с подменёнными ссылками | Была средней, исправлено (S1): только https и подтверждение со списком сайтов |
| Кто-то подменил APK во время раздачи | Зависит от того, как вы раздаёте приложение (S9) |
| Утечка данных на сторону | Низкая: в приложении нет сети и сторонних SDK |
| Кража данных при физическом доступе к разблокированному телефону | Обычный риск телефона, секретов в приложении нет |
| Компрометация вашего GitHub-аккаунта или цепочки сборки | Средняя, если аккаунт без двухфакторной защиты (раздел 6) |

рефлексия, запись чувствительных данных в журнал.

## 6. Для разработчика: репозиторий открытый

### 6.1. Что видно всем

Код и вся история коммитов, ваш логин, Issues и обсуждения, журналы сборок в Actions, скачиваемые артефакты
(3 дня), список «звёзд» и подписок. Всё, что вы когда-либо закоммитили, остаётся в истории даже после удаления файла.

### 6.2. Если вы собираетесь раздавать приложение другим

1. Создайте личный релизный ключ **один раз** и храните копию в надёжном месте (потеряете, и обновить приложение будет нельзя):
   `keytool -genkeypair -v -keystore release.keystore -alias release -keyalg RSA -keysize 4096 -validity 10000`
2. Закодируйте файл (`base64 release.keystore`) и положите в **Settings, Secrets and variables, Actions** как секреты:
   содержимое ключа, пароль хранилища, имя ключа, пароль ключа. В репозиторий ключ не коммитить (`.gitignore` это уже запрещает).
3. Соберите `assembleRelease` с подписью из секретов. Пакет можно оставить тем же, но тогда установленные сейчас
   отладочные версии придётся удалить: подпись другая.
4. Публикуйте APK в **Releases**, а не как артефакт сборки. К релизу приложите SHA-256 файла и отпечаток сертификата
   (`apksigner verify --print-certs`), чтобы пользователи могли проверить подлинность.
5. Отключите отладочный ключ в публичных инструкциях: не предлагайте людям ставить отладочные сборки.

### 6.3. Настройки GitHub, которые стоит включить (бесплатно для публичных репозиториев)

- **Двухфакторная защита аккаунта**, лучше ключ безопасности или passkey. Проверьте список активных сессий и токенов.
- **Settings, Emails**: «Keep my email addresses private» и «Block command line pushes that expose my email».
- **Settings, Code security**: включить Secret scanning, Push protection, Dependabot alerts и **Private vulnerability reporting**
  (тогда люди сообщают об уязвимости приватно через кнопку «Report a vulnerability», и ваша почта не нужна).
- **Settings, Rules**: правило для ветки `main`: запретить force-push и удаление ветки, по возможности требовать успешной сборки.
- **Settings, Actions, General**: для запросов от форков требовать подтверждение запуска; не использовать `pull_request_target`.
- **Gradle**: создать проверку зависимостей командой `gradle --write-verification-metadata sha256 help` и закоммитить
  `gradle/verification-metadata.xml`.
- **Лицензия.** Сейчас файла LICENSE нет, значит по умолчанию все права защищены, и другие не вправе использовать или менять код.
  Выберите лицензию осознанно (например MIT, Apache-2.0 или GPL).
- **Товарные знаки.** Названия ИИ-сервисов используются только как текст, логотипы не включены. Добавьте в README
  строку, что проект не связан с упомянутыми компаниями.
- **Донат.** Ссылка в `Links.kt` будет публичной. Не указывайте в ней личные данные. Используйте страницу сервиса пожертвований.
- **Issues.** Просите не вставлять в них резервные копии настроек, скриншоты с личными подписями и ссылки с токенами.

### 6.4. Если секрет всё же попал в репозиторий

Считайте его скомпрометированным: отзовите и замените (ключ, пароль, токен). Удаление файла и переписывание
истории не гарантируют, что его не скопировали.

## 7. Как проверить самостоятельно

- Телефон: Настройки, Приложения, AI Start, Разрешения: список должен быть пустым.
- На компьютере с Android SDK: `aapt dump permissions app-debug.apk` (нет разрешений),
  `apkanalyzer manifest print app-debug.apk` (экспортированные компоненты),
  `apksigner verify --print-certs app-debug.apk` (отпечаток подписи).
- Android Studio: Analyze, Inspect Code, затем `gradle lint`.
- Автоматический сканер: MobSF (запустить локально, APK никуда не отправляя).
- Сеть: включите на телефоне монитор трафика или брандмауэр и убедитесь, что AI Start не обращается в сеть.
